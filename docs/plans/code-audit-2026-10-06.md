1. **Website rebuild loop** (F1) — `rebuildNow` writes the `Website` row, the
   Prisma middleware treats every `Website` write as a site change and
   re-schedules a rebuild 15 s later, forever. With the PAT broken this is a
   Sentry error every 15 s for every IN_STUDIO/REVIEW/LIVE row; prod's Knight
   Light row is REVIEW, so prod is most likely looping right now.

   also silently deletes their tasks.

# Findings by slice

## Slice A — Tasks & reminders, Send later, Sticky notes

1. **Tier 2 · CONFIRMED — A scheduled invoice goes out with a due date that counted from creation, not from the send, so it can land already past due and start dunning.** `app/api/app/invoices/route.ts:164-169` always stamps `dueDate` at creation (explicit value or `dueDateFromTerms(issuedAt=now)`), and `lib/send-document.ts:227` only recomputes it when `invoice.dueDate` is null, which never happens. Trigger: client on Net 7, create a draft invoice today, Send later for 10 days out; at send time `/app/invoices` lazily flips it to PAST_DUE (`app/platform/invoices/page.tsx:81`) and the past-due reminder/automation path runs. Help (`lib/help/sections/money.ts:24` "the due date counts from then") and the plan both promise the opposite. Fix: in `sendInvoice` when `status === "DRAFT"` and `scheduledSendById` was set (or when `dueDate <= now`), re-derive `dueDate = dueDateFromTerms(now, contact.paymentTermsDays)`; or store a `dueDateFromTerms` flag at schedule time.

2. **Tier 2 · CONFIRMED — A manager dragging a teammate's team note moves it for everyone, not just on their own screen.** `components/sticky/PageNotes.tsx:191` sends `PATCH {x,y}` whenever `n.canEdit` is true, and `canEdit` is true for any OWNER/ADMIN on a shared note (`lib/sticky-notes.ts:51-53`); the server mirrors it at `app/api/app/notes/[id]/place/route.ts:25-28` (`note.userId === actor.id || canEditNote(...)` writes the note's own x/y and deletes the manager's placement). Help says "Positions are per person; only you move what you see" (`lib/help/sections/start.ts:226,244`) and the plan says only the author's drag moves the note. Trigger: staff pins a team note on a job page, owner drags it on their desktop, staff reloads and sees it moved. Fix: client use `n.authorId === meId` (not `canEdit`) to pick PATCH vs PUT /place; server branch on `note.userId === actor.id` only.

3. **Tier 2 · CONFIRMED — Atlas can schedule a send on a non-draft quote/invoice, which then has no chip, no "Scheduled for … · Send now · Cancel" line and no list filter, so it goes out invisibly and can't be cancelled from the UI.** `lib/assistant/money.ts` `email_document` accepts `send_date` for quotes in AWAITING_RESPONSE/CHANGES_REQUESTED and invoices in any status but PAID and stages `/schedule-send`; `scheduleDocumentSend` accepts those (`lib/send-document.ts:464,482`). Every surface keys on `status === "DRAFT" && scheduledSendAt` (`app/platform/quotes/[id]/page.tsx`, `invoices/[id]/page.tsx`, both list pages). Trigger: "Atlas, email quote #12 (already awaiting response) tomorrow at 9" → confirm → nothing on the quote page shows it; the sweep re-sends the next morning. Fix: either reject non-DRAFT in `scheduleDocumentSend` (match the button's `allowLater: status === "DRAFT"`), or render ScheduledSendLine/chip whenever `scheduledSendAt` is set.

4. **Tier 2 · PLAUSIBLE — If the send itself throws (not returns ok:false), the schedule is already cleared and the scheduler never hears about it.** `lib/send-document.ts:362-366` clears `scheduledSendAt` in the claim, then `sendQuote`/`sendInvoice` run; a thrown error from `autoSendQuoteAgreements`, `autoAdvance`, the Prisma update or an email/SMS provider error lands in the `catch` at :400-403 which only `reportError`s — no "Couldn't send" bell/push, document stays a plain draft with no trace of the schedule. Trigger: schedule a quote whose attached agreement template was deleted (or any provider exception) and wait for the tick. Fix: move the failure `notifyUser` into the catch block (same copy as the `!result.ok` branch).

5. **Tier 2 · CONFIRMED — Help Center "Edit: tap the row" is wrong since f97f9139; a row tap opens the read-only details, Edit is a further step.** `app/platform/tasks/TasksClient.tsx:109-116` (`openTask` → TaskDetail, `editTask` from its Edit button) vs `lib/help/sections/start.ts:159` ("**Edit:** tap the row. Everything, including who it's for, can change."). Also "who it's for" only changes for owners/admins. Fix: "tap the row, then `Edit`" and qualify assignment.

6. **Tier 3 · CONFIRMED — Reassigning a task whose reminder already fired never reminds the new person; and a plan-gate gap: reassignment skips the `task_assign` gate.** `app/api/app/tasks/[id]/route.ts:68-71` resets `remindSentAt` only when `remindAt` changed, not when `assigneeId` changes; and the PATCH reassignment path (:48-58) has no `checkFeature(actor.companyId, "task_assign")` while POST does (`tasks/route.ts:56`). Trigger: reminder fires for Dave, owner reassigns to Luis before due → Luis gets the "gave you a task" push but no reminder; with PLAN_GATING=1 a Core company can still hand tasks over via edit. Fix: on assignee change reset `remindSentAt` when `remindAt > now`, and add the gate check.

7. **Tier 3 · CONFIRMED — Help guide title/where still say "on Home" after v4 moved notes to every page.** `lib/help/sections/start.ts:205-208`: title "Sticky notes on Home", `where: { label: "Home" }`, while the summary and body describe any page; `lib/assistant/notes.ts:5` doc comment and tool description also say "sticks to Home" by default (true, but the title misleads a search). Fix: retitle "Sticky notes" / "Sticky notes on any page".

8. **Tier 3 · CONFIRMED — A reminder set in the past fires immediately as "Reminder: …" with no warning at save time.** `lib/tasks.ts:312-324` picks any `remindAt <= now`; the editor/validate path (`lib/tasks.ts:453-469`) never checks the computed instant against now. Trigger: at 10 AM create a task due tomorrow 9 AM with "1 day before" (remindAt = today 9 AM) → push within 5 min. Fix: on create/PATCH, if `remindAt <= now` either return a soft warning or set `remindSentAt = now`.

9. **Tier 3 · CONFIRMED — A scheduled invoice that gets fully paid (Collect Payment, or an edit that makes it fully covered) keeps its schedule; the sweep then fails with a misleading "It's still a draft" card.** `app/api/app/invoices/[id]/route.ts:134-136` flips to PAID without `CLEAR`; payments routes don't clear it either; `lib/send-document.ts:156` then returns "already paid" and :394 appends "It's still a draft — open it to fix and send." Same copy problem for a scheduled quote approved by the client before the time (:55-57) and for the preview-account branch (:371, "this is a preview account It's still a draft"). Fix: clear the schedule on PAID/approval transitions and drop the "still a draft" suffix when `status !== 400`-draft cases.

10. **Tier 3 · CONFIRMED — Send-later default date uses the browser's calendar day, not the company's.** `components/SendChoice.tsx:145-149` `tomorrowISO()` is local-time; the server parses it in the company zone (`lib/send-document.ts:445`). Trigger: owner travelling in a zone ahead of the company, late evening → "tomorrow 9:00" resolves to today 9:00 company time → `past` warning and an immediate send on the next tick. Fix: pass the company's today (server-rendered) into `useSendChoice`, or compute tomorrow via `Intl.DateTimeFormat(timeZone)`.

11. **Tier 3 · CONFIRMED — Done-tab day labels use the browser zone, everything else uses the company zone.** `app/platform/tasks/TasksClient.tsx:363-370` `doneDay` compares `toDateString()` locally. Minor "today/yesterday" drift around midnight for travelling users. Fix: send `doneLabel` from `serializeTask` like `dueLabel`.

12. **Tier 3 · PLAUSIBLE — "Send now" racing the 5-minute tick can email the client twice.** Neither `ScheduledSendLine.sendNow` (`components/ScheduledSendLine.tsx:39-54` → `/send`) nor `sendQuote` takes a lock on the row; if the user presses Send now within the same seconds the sweep claimed the row, both read a sendable status and both send (the sweep's CLEAR only stops a second sweep). Window is seconds; worth a note, not a redesign. Fix: have `/send` refuse when `scheduledSendAt` is null but the page thought it was scheduled (pass `expectScheduled`), or claim in the route too.

13. **Tier 3 · CONFIRMED — A quote whose `validUntil` passes before the send time is still sent (and links to an expired quote).** `scheduleSendWarnings` warns only at scheduling (`lib/send-document.ts:257`); `sendQuote` never checks `validUntil`. Fix: fail the scheduled send with "expired before it could go out" or auto-extend validity.

14. **Tier 3 · CONFIRMED — Managers' Done tab lists everyone's finished tasks, not "my" done tasks, with no label saying so.** `lib/tasks.ts:364` uses `taskScope(actor)` (empty for managers) for `done`; `subFor` only appends the assignee name when `assigneeId !== meId` (`TasksClient.tsx:222`), so it works but the Help FAQ "Where did my finished task go? → the Done tab" reads as personal. Fix: either scope done to self (+ a Team done chip) or state it in the guide.

Looked solid: every new Prisma query is companyId-scoped (tasks GET/PATCH/DELETE/done via `findFirst` + `taskScope`; notes via `findEditable` / `OR own|shared`; placements keyed through the scoped note; schedule-send via `viaContactScope`); role checks match the send routes (canSell for quotes, canSeeMoney for invoices, isManager for team view / assigning / editing team notes; non-managers 403 on assigning; only the author can pin/unpin). Task reminder sweep is idempotent (compare-and-set on `remindSentAt`, skipped when done/inactive/suspended) and fan-out is one task per assignee so each gets their own reminder; editing the reminder time re-arms it. Scheduled-send claim is compare-and-set on `scheduledSendAt` and cleared in the same write, preview accounts are refused both at scheduling and in the sweep, missing email/phone fails gracefully with a bell card, every manual send and every status PATCH leaving DRAFT clears the schedule, quote/invoice editor saves do not touch status so the schedule survives edits as promised. No quiet-hours concept exists for client sends anywhere in lib/, so nothing to respect. Due/expiry parsing goes through `zonedMidnight`/`zonedParts` (DST-safe, day overflow handled by Date.UTC). Sticky bodies render as React text with http(s)-only `<a rel="noopener noreferrer">` (no innerHTML) — no XSS; 400-char cap enforced server-side; caps 30/30 enforced on create and on pin. Right-click is ignored under 1024 px (phones get the strip; long-press on Android can't trigger it), interactive targets / dialogs / selected text are excluded, and components with their own menus win via `defaultPrevented`. Expired notes are hidden on read and archived hourly. Desktop/phone parity for tasks (segmented tabs vs chips, swipe Done/Delete, same groups), for send-later (Modal is a sheet on phones) and for notes (strip ↔ layer) is in place. Help text for reminders ("push + bell", 9 AM for date-only tasks, ~5 min) matches the code (no email fallback exists in code and none is promised). Shortcuts `g k` / `n t`, Create tile prefill (`contactId`/`jobId` resolved server-side), nav badge, Needs you / Today wiring, Atlas `add_sticky_note` registration and the `task` bell kind all check out. Company delete cascades tasks and notes.
